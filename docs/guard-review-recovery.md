# 回退审核故障与恢复

## 问题与修复边界

1.16.2 的一次真实调用在主决策模型完成后进入回退审核。回退请求失败，插件返回 `fallback-review-failed`，随后把这次失败放进120秒判定记忆。73秒后的同参数重试直接复用旧失败，没有再次请求回退服务。服务或余额即使已经恢复，这次重试也无法验证恢复状态。

此次修复区分两种结果：

- **有效裁决**：模型完整返回符合协议的 `allow` 或 `deny`，以及显式配置的回退政策结果，可继续复用。
- **执行故障**：请求异常、宿主错误结束、超时、模型不可用、输出不完整或不符合协议，不写入裁决记忆。当前调用仍按既有规则拒绝或取消；下一次正常发起的调用重新审核，不把故障当成许可。

不会自动重发被拒的工具，不会自动执行之前的命令，也不因余额充值、聊天同意或模型异常授予权限。强制审批、工具访问限制和执行前身份/参数校验保持不变。

## 脱敏诊断

回退故障在 `modelEvaluation.fallback.failure` 中保留结构化诊断，字段限定为：

- `stage`：失败所在阶段，例如请求、流结束、输出读取或答案解析。
- `code`：白名单错误码或固定的本地协议故障码；未知错误不复制任意字符串。
- `httpStatus`：有可靠数值来源时保留 HTTP 状态，否则为空。
- `finishReason`：宿主流的固定结束原因；没有该信息时保留未知状态。

诊断不保存原始错误消息、响应正文、URL、请求头、凭据或模型原始输出。主原因 `fallback-review-failed`、`review-timeout` 等继续用于兼容现有界面和审计；子分类用于区分请求故障与协议故障。

例如，宿主明确报告 `QUOTA` 才能据此判断额度问题。只有 `fallback-review-failed` 或一次很短的耗时，无法证明余额、网络或鉴权中的哪一项失败。`reasoningEffort=off` 在已核验的 DSH DeepSeek provider 中合法，不应仅凭该值更改用户配置。

## 复用与耗时

`reused=true` 表示本次复用既有有效裁决，不代表重新发出了模型请求。复用评估的延迟不再作为本次网络耗时重复累计。旧日志不会被重写；旧版本失败记录里保留的延迟仍属于原始请求。

## 回归要求

使用隔离模型桩验证：

1. 回退失败后，替换为正常模型桩，同参数新调用必须重新审核。
2. 明确返回 `deny` 的有效审核继续复用，不能通过反复调用改变结论。
3. 主模型故障、回退超时或不可用不形成可复用故障。
4. caller 取消不转换为放行，也不写入裁决记忆。
5. 宿主错误结束、缺少结束事件、输出超限、非法 JSON 和非法答案结构有可区分的诊断。
6. 错误对象中的凭据 canary、URL、正文及未知错误字符串不能出现在返回对象或日志中。

测试仅验证判定与错误处理路径，不调用真实付费模型，也不执行真实危险工具。
