## 0. 总原则与安全边界

- 保持 fail-closed。不为减少 deny 放宽判定，不加 fail-open，不因查询或回退失败一律放行。
- 不默认切换模型或 effort 档位。更换回退模型、改 `guardFallbackReasoningEffort` 都是配置变更，另需授权。
- 不修改运行中的 DSH profile 和全局配置。Git 回滚只作用于本仓库，管不到已安装的插件和 profile。
- 安装、重启、canary、推送、发布各自需要用户明确授权。本文列的是计划，没有一项已经执行。
- 测试只用隔离 fixture 和虚构资源，不做真实删除、提权或外网副作用。日志不复制原始 JSONL、路径正文和参数。
- 关键修复由独立只读角色验收，不采信实现者自评。验收不通过就退回，不勾待办。
- 宿主最终边界不变：越级请求继续拒绝，未知权限不放宽。

## 2. 阶段 1：P1 代码修复

由根流程派发的两个代码任务实施（任务 20、21）。两项必须在代码完成、独立验证通过后才能在 TODO 勾选。

### LOG-001 回退 effort 能力预检与明确失败语义

问题：30 次 `codex-proxy` / `codex-auto-review` / `off` 回退全部返回 `UNSUPPORTED_REASONING_EFFORT`，宿主在 provider I/O 前拒绝。调用侧没有提前检查，也没有可操作的提示。

方案：
- 进入回退前预检所选模型是否支持配置的 effort。能力信息取不到时按不支持处理，并给出明确失败，不静默降级。
- 不支持时返回带原因和修复方向的失败，不发起 `llm.stream`，不重试同一组合。
- 失败裁决不写缓存、不复用。
- 不自动改 effort 或模型。

依赖：回退实现 [lib/guard/fallback.js](../../lib/guard/fallback.js) 与现有能力信息来源。
验收：fixture 覆盖支持与不支持两组；不支持组不触发 `llm.stream`，提示可操作；支持组正常回退；失败不缓存。
回滚：仓库内 `git revert`。已安装插件不受影响，除非另获授权安装。
验收结果：独立只读角色确认 Guard 定向测试 `484/484`、隔离安全情景 `96/96`、`vp run verify:wiring` 均通过。默认并发全量测试有 Windows 临时目录清理 `EPERM`，串行运行 `1366/1366` 通过；该失败不涉及本阶段新增回退预检或权限分类代码。结果只证明仓库代码，不证明当前 profile 已安装或线上已运行。
安全边界与未决：当前 `off` 与所选模型能力失配是现网配置问题，需单独授权后才能改配置。代码修复完成不等于该失配已解决，LOG-001 整体勾选要等配置问题有结论。

### LOG-002 无效权限请求与真实提权分类

问题：2 次有效权限为 full、请求 workspace-write 的组合，宿主判为 `SANDBOX_ESCALATION_INVALID_ARGUMENT`，不是审批请求，但插件把它与真正提权混在一起。

方案：
- 分开归类：同模式、无效值、更窄、越级、未知工具。
- 拒绝提示说明实际触发项。
- 更窄的无效请求不静默放行，越级继续拒绝，错误码保持兼容，未知权限不放宽。

依赖：宿主 `escalation.ts` 的行为作为只读参照，不修改。
验收：fixture 五类齐全；提示指向真实触发项；错误码兼容。
回滚：仓库内 `git revert`。
安全边界：不改变任何放行条件，只改分类和提示。
验收结果：独立只读角色确认 Guard 定向测试 `484/484`，隔离安全情景 `96/96`；覆盖同级、无效值/类型、更窄请求、真实越级和未知工具。`full → workspace-write` 归无效参数并本地拒绝，真正越级仍保留原审批边界。结果只证明仓库代码，不证明线上 1.16.4 行为。

## 3. 阶段 2：LOG-004 脱敏审计字段

问题：`hostFinalAction` 恒为 `unknown`，缺独立 `requestedMode`、canonical、`roots` 和部分关联字段。

方案：
- 先查清 `hostFinalAction` 为什么恒为 `unknown`：是宿主没给，还是插件没读。
- 补 `requestedMode`、canonical 判定、`roots` 的摘要和关联标识。只记录类别、计数、哈希或截断标识，不记录原始路径和正文。
- 非 authorize 记录单独建模，不进调用分母。
- 增加结果证据字段，使任一调用能回答候选、实际、模式和宿主结果。

依赖：阶段 1 的分类结果可复用，字段设计不应与之冲突。
验收：任取一条调用可还原候选、实际、模式、宿主结果；非 authorize 有独立分母；新增字段通过脱敏审查，没有路径、参数正文或凭据。
回滚：字段只增不改，`git revert` 即可。读取方应容忍字段缺失。
安全边界：日志体量不显著增加，不写原文。
